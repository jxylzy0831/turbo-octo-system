# StageFlow 项目约定

本目录开发剧本互动 3D 预演程序。遵守上级原始资料保护、垃圾箱排除及会话记录规定。程序开发不改写原剧本事实。

- 已明确选用 Three.js 网页交互方案，不引入 HyperFrames 作为预演框架。
- 业务对象分别放在独立 TypeScript 模块中。index.html 仅保留容器和模块入口，不内联场地、台词、CSS 或交互逻辑。
- 人物 ID 固定为 N1 至 N4、P1 至 P4、G。共享 Actor 类，通过配置表达差异；不要为九个同构人物复制九份程序。
- 房间为一个物理房间。中央幕布把它等分为北侧演绎区与南侧玩家区，不当成两个独立房间。
- 北门用于 NPC 入场，南门用于玩家入场。闭幕阻挡视线与过幕走位，不默认隔音。
- domain 层不依赖 Three.js、DOM 或音频 API。显示层不判断剧情分支。流程层通过接口调用能力，依赖由 App 在入口组装。
- 台词、示例流程、人物配置与房间尺寸由数据表达，不写进人物建模代码。示意值与实测值区分。
- 演示玩家回应必须标注为示例，不当成真实玩家已作的选择。
- 语音文件按人物和台词 ID 关联，人物不用录音也能演示气泡。没有语音时等待状态仍可手动推进。
- 新代码不修改 drafts 中的剧情文本。新剧情提案按上级目录约定另存。
- 只有用户要求时添加或运行测试。不要把演示截图、构建产物或依赖提交到 Git。
