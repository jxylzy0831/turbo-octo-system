# 剧本互动设计 · 通用版

从互动发生的原因出发，设计玩家能够进入、演员能够接住、在实际房间里能够执行的场景。把文本案例当作机制的证据与启发，提出有条件的解释，不保证所有玩家都会笑、哭或投入。

## 默认演出条件

只有一个房间，由幕布分隔为**玩家区**与**演绎区**，音乐和灯光可控。这是当前用户确认的默认空间条件。故事可跨年代、跨地点，实际执行仍须落回这两区。

- 幕布提供视觉遮挡，不默认隔音。闭幕后演员对白、布景声音仍可能被听见。
- 演绎区同时承担表演、等待出场、道具准备的需求；不能无条件当成无限后台。
- 不默认有第二房间、走廊舞台、第三名演员、独立音控、分区灯、追光、无线耳返或投影。需要时先查现有配置；未知时提供现有条件可执行的方案。
- 场上观众看见一段回忆，不自动等于角色在故事中亲历或获知。写清现实位置、故事时空和知情状态。

用户另行指定场地时更新条件。保持机制通用，不把这个房间的未知尺寸与设备当成全行业标准。

## 如何开展任务

### 先确定本段需要改变什么

用一句具体变化描述目标，例如“甲第一次知道乙也曾照顾同一人，并能借这件事向乙开口”。“热闹一点”“拉羁绊”“刀玩家”是需求线索，需要继续落实为认知、关系或行动变化。

同时记录起点：玩家刚读到什么、现在想做什么、是否理解规则、谁仍在读本、当前是轻松还是紧张。角色的愿望与玩家的表达习惯分开考虑；不把安静直接解释成冷漠。

### 再写出互动的因果链

**人物此刻的需要 → 合理邀请 → 玩家能做的小动作 → NPC/同伴的具体回应 → 可观察的变化 → 留下的记忆或下一步。**

按这条链推敲场景，不要求每段都塞进笑点、物件、秘密或反转。判断“为什么这样互动”时问：删掉这一步，哪一项必要作用会消失？换一个时代、称谓和物件，这项作用还能否成立？

设计解释与薄弱方案诊断，读 [互动机制](参考资料/互动机制.md)。学原作时还要保留原文不顺、强预设和缺少分支的地方，不用理想化改写冒充事实。

### 把玩家的输入接到后果上

明确本段自由的是表达、方法、顺序、关系态度还是剧情结果。固定结局也可以容纳真实的回应；道具可自由选择也不等于结局有分支。

NPC 既有自己的欲望，也有主持职责。写出“他想得到什么、怎样追问、听到不同答案如何改变措辞或动作、何时让出话权”。不用演员独白、点名或观众鼓掌代替玩家互动。

场内争执、隐瞒、诱导与倒计时可服务故事；玩家对表演形式的退出，与角色在剧情里输赢分开处理。允许角色反对 NPC，不把玩家的拒绝接触或暂停当成剧情失败。

### 最后排进同一个房间

逐段标注注意力焦点、演员位置、幕布状态、道具交接、声光触发和下一位接话者。玩家区的互动与演绎区的备场必须共享同一份时间表。

每个关键提示写“谁观察到什么之后执行”，不依赖玩家说出唯一预写句子。只有固定录音或固定表演内部才适合精确时间码；玩家回应段采用事件触发。

排演与资源校核读 [单房间执行](参考资料/场景与提示.md)。台词、分支与全幕文件按 [交付模板](参考资料/设计模板.md) 选择所需部分，不机械填满所有表。

## 按任务选择材料

- **学习新手册**：先抽出事实链，区分原文、研究解释和新设计；参照 [案例与证据](参考资料/证据与案例.md)。关键 OCR 错序或说话人不明处回查源页，不能靠旧 HTML 标签判定。
- **破冰或日常互动**：优先检查邀请理由、最小参与动作、玩家之间的真实往返、共同记忆如何保留。熟人局不必重做陌生人介绍。
- **关系冲突或剧情揭晓**：优先检查信息权限、立场、解释空隙、当事人的回应位置与收场条件。故事紧张不必转成轻松笑场。
- **告别与情绪回收**：寻找玩家曾实际参与过的细节，改变它的意义或交接方式。没有前置就承认需要补建，避免临终集中新增回忆。
- **检查已有流程**：定位因果断点与资源冲突，说明改动及其代价；不顺便重写全部角色与剧情。

## 判断是否完成

1. 解释了这段互动为何适合这些人物、这个时刻，以及预期作用在哪些情况下会失效。
2. 玩家能理解自己的入口；主动、简答、沉默、不同意和提前完成均有合理接法。
3. 有群体目标时，玩家彼此发生了回应或协作；有观演目标时，允许安静观看，不为全员轮流发言破坏戏。
4. 每个角色的故事立场、玩家知情范围与允许改变的事项清楚；不临时编造关键真相。
5. 两区、幕布、演员、道具和声光没有同时占用冲突；技术失效后核心互动仍能继续，或有明确暂停点。
6. 原文要求、机制假设、用户新设定、原创流程及实跑反馈能区分。已完成文本设计不等于验证现场效果。
